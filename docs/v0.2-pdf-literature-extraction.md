# v0.2 PDF 文献信息读取设计文档

这份文档用于规划下一阶段的 PDF 文献信息读取能力。它不是承诺已经上线的功能，而是给用户、贡献者和未来 Pro 版本使用的产品边界说明。

## 目标

v0.2 的 PDF 能力目标不是“自动代写论文”，而是减少用户从 PDF 原文里手动摘录题名、作者、摘要、关键词和参考文献的时间。

理想流程是：用户提供 PDF 或 PDF 中复制出的文本，工具先提取可识别的文献信息，再生成文献覆盖表、缺失字段提醒和后续文献综述提示词。

## 免费版边界

免费网页版 v1 仍然保持静态网页形态：

- 不上传 PDF 到服务器。
- 不保存用户文件。
- 不直接解析 PDF 正文。
- 只把用户选择的 PDF 文件名写入提示词，提醒用户到 ChatGPT、DeepSeek、豆包、通义等支持文件上传的 AI 工具里同步上传 PDF。
- 如果用户愿意，也可以自己从 PDF 中复制标题、摘要、关键词、参考文献，再粘贴到文献资料框。

免费版适合做“PDF 使用说明”和“提示词生成”，不适合在浏览器里做复杂 PDF 解析。

## Codex Skill 开源版规划

Codex Skill 开源版可以优先支持以下轻量能力：

1. 读取用户粘贴的 PDF 摘要、参考文献页、题录文本。
2. 从复制文本中提取作者、年份、题名、期刊或来源、摘要、关键词、DOI/URL。
3. 对字段缺失的文献标记“需要人工核验”。
4. 把 PDF 来源文献整理进文献矩阵。
5. 在生成综述前提示用户核验作者、年份、题名和来源。

开源版不做：

- 绕过数据库下载限制。
- 自动破解 PDF、验证码或机构权限。
- 把字段不完整的 PDF 文献写成正式引用。
- 承诺提取结果完全准确。

## Pro 版规划

Pro 版可以考虑做更完整的 PDF 文献处理：

- 网页内上传 PDF。
- 自动提取题名、作者、摘要、关键词、参考文献列表。
- 自动识别中文期刊题录和英文 DOI。
- 多篇 PDF 批量处理。
- 生成字段完整性报告。
- 标记疑似重复文献、缺字段文献和待核验文献。
- 将核验后的文献写入综述包。
- 与 Word 导出、GB/T 7714 格式化联动。

Pro 版仍然必须遵守边界：不绕过 CNKI、万方、维普、学校图书馆和期刊官网的权限限制；公开候选和机器提取内容必须经过人工核验。

## 推荐输入格式

如果用户暂时不能上传 PDF，建议先手动复制这些信息：

| 字段 | 说明 |
| --- | --- |
| 作者 | 尽量保留完整作者名 |
| 年份 | 发表年份，不确定时标记“待核验” |
| 题名 | 论文标题，避免只写简称 |
| 期刊或来源 | 期刊名、会议、学位论文或数据库来源 |
| 摘要 | 用于判断研究主题、方法和结论 |
| 关键词 | 用于生成检索式和主题分组 |
| DOI/URL | 用于后续核验 |
| PDF 来源 | CNKI、万方、维普、学校图书馆、期刊官网或公开网页 |

## 处理流程

1. 用户上传 PDF，或粘贴 PDF 中复制出的文本。
2. 工具提取候选字段。
3. 工具生成“PDF 文献字段检查表”。
4. 字段完整的文献进入文献矩阵。
5. 字段不完整的文献标记“需要人工核验”。
6. 用户确认后，再生成文献综述提示词或综述草稿要求。
7. 最终引用仍以数据库、期刊官网、DOI 页面或原文为准。

## 核验规则

- 不能根据 PDF 文件名猜测作者、年份或期刊。
- 不能把“可能是标题”的文本直接当正式题名。
- DOI、URL、期刊名缺失时，需要明确标记。
- PDF 中提取出的参考文献列表不能直接证明“谁引用了谁”，除非用户提供原文证据。
- 如果同一篇文献从多个来源出现，需要合并并标记重复来源。

## 验收标准

v0.2 原型至少应做到：

- 用户能看懂免费网页版目前为什么不能直接解析 PDF。
- 用户知道 PDF 应该怎么配合提示词使用。
- README、网页版和 SHARE 中能看到 PDF 读取 Roadmap 入口。
- GitHub Issue #3 可作为 PDF 需求反馈入口。
- 不出现“自动生成正式引用”“无需核验”等误导性表述。
